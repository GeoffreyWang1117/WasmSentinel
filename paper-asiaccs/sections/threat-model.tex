\section{Threat Model}
\label{sec:threat}

\sys is a host agent. A small, fixed set of eBPF programs it ships observes
process, file and network activity on a Linux host; a user-space daemon
turns those observations into events; and a set of \emph{rules}, each a
WebAssembly module, decides for every event whether it is worth an alert.
The rules are the part that changes: they are written by security teams,
shipped by vendors, pulled from community packs, updated independently of
the agent, and in the case of \texttt{ml\_detector} they embed a model
trained elsewhere. Our threat model is about that boundary.

\paragraph{Trusted.}
The kernel and its eBPF verifier; the eBPF programs and the record layout
\sys ships (a few hundred lines, fixed at build time, \S\ref{sec:design});
the Go daemon; and the Wasmtime runtime, including its compiler and its
enforcement of memory, fuel and epoch limits. A bug in any of these is a
bug in the trusted computing base and is out of scope here, with the usual
caveat that the eBPF verifier has had bypasses~\cite{ebpf-bugs} and that we
keep the eBPF side small for exactly that reason.

\paragraph{Untrusted.}
Every rule module. A rule may be buggy (an unbounded loop on an unexpected
event, a quadratic data structure, a memory leak per process) or malicious
(a module that reads \texttt{/etc/shadow} or a credential file, opens a
socket, inspects the daemon's environment, or simply burns CPU so that
another vendor's rule never runs). We also treat the monitored workload as
adversarial in the narrow sense that it controls the \emph{content} of
events: command lines, paths and syscall sequences are attacker-chosen
bytes, and a rule must be able to receive any of them without the daemon
being affected.

\paragraph{What the sandbox must guarantee.}
For every rule, regardless of its code: (1)~\emph{no ambient capability}:
no file system, no network, no environment, no process control; the only
host import is a clock; (2)~\emph{bounded resources per call}: linear memory
capped, an instruction budget (fuel) and a wall-clock deadline per
invocation; (3)~\emph{failure isolation}: a rule that traps, exhausts its
budget or exits is dropped and re-instantiated, the event continues to the
remaining rules, and no rule can observe or modify another's memory;
(4)~\emph{the decision is the rule's own}: the host neither interprets nor
post-processes the verdict beyond mapping an integer to a severity.
\S\ref{sec:eval:e6} tests (1)--(3) with modules written to violate them.

\paragraph{Out of scope.}
Side channels between rules or against the host (CT-Wasm~\cite{ct-wasm}
addresses one class); escapes through runtime bugs; evasion of a rule's
detection logic by mimicry or adversarial inputs, which is a property of the
rule and not of the sandbox; denial of service against the \emph{kernel}
side, e.g.\ a workload that produces events faster than the ring buffer
drains, which \sys counts but does not prevent; and the integrity of the
alert channel after the daemon has emitted an alert. Sandboxing does not
make a rule correct: a contained rule can still have a false-positive rate
of one, and \S\ref{sec:eval:e1} reports accuracy for that reason.
